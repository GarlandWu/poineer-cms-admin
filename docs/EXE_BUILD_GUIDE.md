# 能源门户管理工具 EXE 打包指南

## 概述

将 Next.js + Payload CMS 项目打包成一个独立的 Windows exe 文件，供运营人员使用，包含以下功能：

- **启动 CMS** — 本地编辑和管理内容（端口 3001）
- **预览网站** — 查看最新的静态站点构建产物（端口 5000）
- **一键发布** — 自动执行构建 + Git 推送到服务器

---

## 打包步骤

### 1. 安装依赖（仅需一次）

```bash
npm install -g pkg
```

或在项目目录中：

```bash
npm install
```

### 2. 生成 EXE 文件

```bash
npm run pkg
```

打包脚本会：
- 检查 `pkg` 是否安装（未安装则自动全局安装）
- 编译所有代码和资源
- 输出 `dist/EnergyPortalManager.exe`

**打包耗时**：3-5 分钟（首次较长）  
**文件大小**：~60-80MB（包含 Node.js 运行时）

### 3. 验证 EXE

打包完成后，双击 `dist/EnergyPortalManager.exe` 验证运行。

## 使用方法

### 启动 EXE

双击 `EnergyPortalManager.exe`，出现菜单界面：

```
╔════════════════════════════════════════════════════════════════╗
║           能源数字孪生门户 CMS 发布管理工具                    ║
║                  Energy Portal Manager v0.1                    ║
╚════════════════════════════════════════════════════════════════╝

请选择操作:

  [1] 启动 CMS 后台
  [2] 预览站点 (本地构建产物)
  [3] 一键发布 (构建 + 推送)
  [0] 退出

请选择 (0-3):
```

### 选项 1：启动 CMS 后台

```
[1] 启动 CMS 后台
```

- 启动本地 Payload CMS 服务
- 访问地址：**http://localhost:3001**
- 编辑内容、新增产品、发布新闻等
- 按 `Ctrl+C` 停止

**首次启动**：会自动检查 `cms/` 目录下的依赖，初始化可能需要 1-2 分钟。

### 选项 2：预览站点

```
[2] 预览站点 (本地构建产物)
```

- 如果 `out/` 目录不存在，会先执行构建
- 启动 HTTP 服务提供本地预览
- 访问地址：**http://localhost:5000**
- 可以预览最后一次构建的网站
- 按 `Ctrl+C` 停止

### 选项 3：一键发布

```
[3] 一键发布 (构建 + 推送)
```

执行完整的发布流程：

1. **构建 CMS** — 从 Payload 导出最新数据
2. **构建站点** — 编译 Next.js 静态站点到 `out/`
3. **清理 Submodule** — 清空 `pioneer-cms/` 目录（保留 .git）
4. **复制产物** — 将构建产物复制到 `pioneer-cms/`
5. **Git 提交** — 自动 commit 和 push 到服务器

**耗时**：5-10 分钟（取决于项目大小和网络速度）

发布完成后，会返回菜单界面。

## 项目目录结构要求

EXE 能正常运行需要以下目录结构：

```
项目根目录/
├── EnergyPortalManager.exe     ← 运行这个文件
├── cms/                        ← Payload CMS 项目
│   ├── package.json
│   ├── src/
│   └── ...
├── src/                        ← Next.js 源码
├── public/                     ← 静态资源
├── scripts/
│   ├── build.js              ← 构建脚本
│   ├── export.js             ← CMS 导出脚本
│   └── publish.js            ← 发布脚本
├── out/                        ← 构建产物（首次运行时生成）
├── next.config.js
├── tsconfig.json
├── package.json
└── ...
```

**关键点**：
- EXE 必须与项目根目录在同一目录下运行
- 或将项目整个目录打包成压缩包分发给运营人员

## 常见问题

### Q: EXE 文件很大（60-80MB），能否缩小？

**A:** 文件大小包含完整的 Node.js 运行时。这是打包独立可执行程序的代价。
- 优点：不需要用户安装 Node.js，开箱即用
- 若要缩小，需放弃离线能力，改为动态下载 Node.js（不推荐）

### Q: 能否在其他电脑上使用？

**A:** 可以。将 EXE 和整个项目目录复制到其他 Windows 电脑，双击即可运行。

### Q: CMS 依赖未安装怎么办？

**A:** 首次运行 `[1]` 或 `[3]` 时会自动检查并安装。请确保网络连接正常。

### Q: 如何更新 EXE？

**A:** 修改代码后，重新运行 `npm run pkg` 生成新的 EXE。

### Q: 为什么启动 CMS 很慢？

**A:** 首次启动时：
- 安装依赖（`npm install`）
- 初始化数据库（SQLite）
- 编译 Payload CMS

通常需要 1-2 分钟。后续启动会快一些。

### Q: 发布时 Git push 失败了怎么办？

**A:** 检查以下几点：
1. 网络连接是否正常
2. Git 凭证是否有效（SSH 密钥或 Personal Token）
3. Git 配置（`git config user.name` / `user.email`）
4. `pioneer-cms/` submodule 是否已正确配置

可以手动在命令行中进行 Git 操作：

```bash
cd pioneer-cms
git status
git push origin main
```

## 分发给运营人员

**推荐方式**：

1. 将项目整个目录压缩成 zip
2. 或打包成安装程序（可选，需要额外工具如 NSIS）
3. 提供使用说明文档

**文件清单**（可删除以减小大小）：
- `.git/` 目录（保留或删除都可以）
- `node_modules/`（EXE 已包含）
- `.next/` 构建缓存（可删除）
- `.env.local`（敏感信息，确保安全）
